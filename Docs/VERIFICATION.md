## 1. 세션 3-4 — 낙하 버그 수정 + 에셋 스왑

### 1-1. 보스 타일이 벽을 우회해 내려오는가 (버그 수정 확인)
**왜**: 벽에 얹힌 타일이 미끄러지는 규칙이 없어서 보스가 공중에 멈춰 있었다. 리필이 기둥 중간을 가로채는 문제도 함께 고쳤다.

- [ ] 벽(W)이 있는 스테이지(**1-1**)로 Main 진입
- [ ] 보스 타일이 스폰될 때까지 플레이 (점수/시간이 쌓이면 확률 상승)
- [ ] **보스 타일이 벽에 막히면 대각선으로 미끄러져 내려오는가**
- [ ] **벽(W)/구멍(X)이 아닌 칸에 빈 칸이 남지 않는가** (한 칸이라도 계속 비어 있으면 버그)

> 의도된 동작: 보스가 벽 위에 얹힌 동안은 대각선이 열릴 때까지 기다린다(그동안 카운트다운 압박 = 기획 의도).
> 전투 돌입 판정은 "열 최하단 활성 셀 도달" 그대로.

### 1-2. 타일 스프라이트가 실제로 표시되는가 (A2 파이프라인)
- [ ] `Assets/_Project/Data/Tile_*.asset` 중 아무거나 골라 `sprite` 슬롯에 이미지 하나 꽂기
- [ ] Main 플레이 → **해당 타일이 색 사각형 대신 그 스프라이트로 나오는가** (스프라이트 지정 시 흰 틴트 = 원색)
- [ ] (선택) `BoardView`의 `wallSprite` / `bossSprite` / `cellSprite` 슬롯도 같은 식으로 동작하는지

## 3. B3 — 스테이지 기믹 3종 (월드2)

배선: **2-1 = 사슬 / 2-2 = 사슬 + 시한폭탄 / 2-3 = 사슬 + 폭탄 + 전염**, 월드1은 기믹 없음.
수치는 `StageDataSO ▸ Gimmick Tuning`에서 조절 (확률/턴/피해량).

### 3-1. 사슬 결박 (2-1)
- [ ] 회색 띠가 감긴 타일이 **시작부터 3개쯤** 보이는가 (`chainInitialCount` 기본 3)
- [ ] 결박 타일을 **드래그해도 스왑이 안 되는가** (턴도 안 닳아야 함)
- [ ] 위 타일들이 결박 타일 **위에 쌓이고, 그 아래로는 안 내려가는가** (벽과 같은 취급)
- [ ] 결박 타일이 포함된 매치 → **타일은 남고 사슬만 풀리는가** (영혼석도 안 나옴)
- [ ] 사슬이 풀린 뒤에는 정상 낙하/스왑되는가

### 3-2. 시한폭탄 (2-2)
- [ ] 새로 떨어지는 타일 일부에 **빨간 숫자**가 붙는가 (기본 확률 12%, 시작값 3)
- [ ] 턴을 넘길 때마다 숫자가 **1씩 줄어드는가** (스폰된 그 턴은 안 줄어드는 게 정상)
- [ ] 0이 되면 **타일이 사라지고 HP가 깎이는가** (기본 12)
- [ ] 카운트 안에 매치로 없애면 아무 일도 안 일어나는가
- [ ] 폭발로 생긴 빈 자리가 정상적으로 메워지는가 (그 결과 매치가 터지면 영혼석도 들어옴)
- [ ] HP가 0이 되면 **DEFEAT 화면**으로 가는가

### 3-3. 전염 (2-3)
- [ ] 보라색 부패 타일이 **시작 시 2개** 있는가
- [ ] 턴이 지날 때마다 **인접 타일 하나씩 부패로 바뀌는가**
- [ ] 부패 타일은 **스왑도 매치도 안 되는가**
- [ ] 부패 **바로 옆에서 매치를 터뜨리면 부패도 같이 사라지는가**
- [ ] 부패가 보드의 35%쯤에서 **더 이상 안 퍼지는가** (완전 데드락 방지 장치)

### 3-4. 조합 / 안정성 (2-3에서 같이 보기)
- [ ] 사슬 + 폭탄 + 전염이 한 보드에서 동시에 굴러가도 멈추거나 예외가 안 나는가
- [ ] **콘솔에 에러/예외 0개** (특히 `InvalidOperationException: 이미 타일이 있는 셀`류)
- [ ] 둘 곳이 없어서 게임이 진행 불가로 굳는 상황이 생기는가 (생기면 §8 양식으로 재현 절차 기록)

> 특히 봐줬으면 하는 것 — 내가 코드로는 못 잡는 부분:
> ① **폭발 → 낙하 → 새 매치**로 이어지는 연출 순서가 어색하지 않은지
> ② 매치가 통째로 사슬에 막혔을 때(전부 결박) 사슬만 풀리고 턴이 소모되는데, 이게 손해처럼 느껴지는지
> ③ 기믹 3개가 겹친 2-3의 **체감 난이도** — 수치는 인스펙터에서 바로 조절 가능

## 4. B4 — 모바일 세로/가로 뷰 대응

**먼저 빌더를 다시 돌려야 한다** (방향 프리셋이 빌더에서 깔린다):
- [ ] `Main.unity` 열고 `Tools ▸ ChainRiposte ▸ Build Main Scene UI`
- [ ] `StageSelect.unity` 열고 `Tools ▸ ChainRiposte ▸ Build StageSelect Layout`

### 4-1. 세로(기존) 배치가 그대로인가
- [ ] Game 뷰를 **1080×1920** 으로 두고 Main 플레이 → HUD/전투/결과가 기존과 동일

### 4-2. 가로에서 성립하는가
- [ ] Game 뷰 해상도를 **1920×1080** 으로 바꾸기 (플레이 중에 바꿔도 즉시 반영돼야 정상)
- [ ] 전투: **PARRY = 왼쪽 사이드 / ATTACK = 오른쪽 사이드**, 보스·게이지가 화면 안에 들어오는가
- [ ] 퍼즐: +ATK/+DEF/+PARRY 버튼이 **오른쪽에 세로로** 쌓이고 보드를 심하게 가리지 않는가
- [ ] 월드맵: 정보 패널이 **오른쪽 컬럼**으로 서고 START가 그 아래에 붙는가
- [ ] 보드/월드맵이 화면에 꽉 차게 다시 맞춰지는가 (카메라 자동 재조정)
- [ ] UI가 통째로 확대/축소돼 보이지 않는가 (기준 해상도 전환)

### 4-3. 배치가 마음에 안 들 때 (여기가 이번 작업의 핵심)
- [ ] 아무 UI 요소나 골라 씬 뷰에서 원하는 위치로 드래그
- [ ] 인스펙터의 `Orientation Layout ▸ **가로(Landscape)로 저장**` 클릭
- [ ] `가로 미리보기` / `세로 미리보기` 버튼으로 두 배치가 번갈아 적용되는가
- [ ] 플레이해서 해당 방향에서 저장한 대로 나오는가

> 코드 수정 없이 배치를 잡는 게 목적이다. 마음에 드는 값이 나올 때까지 드래그 → 저장을 반복하면 된다.
> 컴포넌트가 없는 요소는 `Add Component ▸ Orientation Layout` 으로 붙이면 현재 배치가 양쪽 프리셋에 들어간다.

## 5. 데드락 리롤 (둘 수 있는 수가 없을 때 보드 섞기)

빌더 재실행이나 씬 배선은 **필요 없다** — 기존 배너 텍스트를 그대로 쓴다.

**왜 중요한가**: 매치가 없는 스왑은 턴을 소모하지 않으므로, 수가 하나도 없으면 턴이 영영 안 넘어간다.
그동안 보스 카운트다운의 **실시간 축은 계속 흐르므로** 아무것도 못 하는 채로 지는 상태가 된다.

- [ ] 자연 발생을 기다리기 어려우면 **2-3(사슬+폭탄+전염)**에서 판이 조각날 때까지 플레이
- [ ] 수가 없어지는 순간 타일들이 **한꺼번에 새 자리로 날아가는가**
- [ ] 배너에 `NO MOVES — SHUFFLING` 이 잠깐 뜨는가
- [ ] 리롤 뒤에 **턴 수가 그대로인가** (리롤은 턴 미소모)
- [ ] 리롤 직후 **매치가 저절로 터지지 않는가** (공짜 콤보 금지)
- [ ] **벽·보스 타일·사슬 타일·부패 타일은 제자리에 있는가** (보스는 하강 위치가 곧 게임플레이라 절대 안 섞음)
- [ ] 폭탄 타일이 자리를 옮겨도 **숫자가 그대로 따라가는가**

> 규칙상 섞이는 건 '움직일 수 있는 타일'뿐이다. 자유 타일이 극단적으로 적은 판(대부분 사슬·부패)에서는
> 섞어도 답이 안 나올 수 있는데, 그건 스테이지 수치 문제이므로 §8 양식으로 적어주면 튜닝하면 된다.

### 7-5. 보스 전투 (여기가 이번 핵심)

- [ ] 보스 타일 도달 → **준비 화면**이 뜨는지 (예외 없이). 경고 문구 + NPC 자리 2개

- [ ] 회색 띠가 눈에 들어오는지 / `+PARRY`를 찍으면 **띠가 굵어지는지**
- [ ] **패링이 손에 맞는지** — 빡빡하면 `PlayerStatsConfig ▸ parryLateGraceSeconds`(0.12)를 올린다
- [ ] Flurry 패턴의 **3연타**에서 원 3개가 줄지어 오고, 패링 3번으로 다 막히는지
- [ ] 공격 버튼 — **빈 박에서만** 나가고, 노트가 올 때 누르면 잠기는지 / 찌르는 모션이 보이는지

## 8. 세션 6 (2026-07-23) — 캐릭터 선택 + NPC 반응

### 8-0. 먼저

      (캐릭터와 무관하므로 코드는 성녀만 채운다)

### 8-1. 캐릭터 선택

- [ ] 타이틀 ▸ 새 게임 → (세이브가 있으면 확인 후) **캐릭터 선택 화면**이 뜨는지
- [ ] 카드 2장(기사 / 낭인)이 그림과 이름으로 나오는지, 고른 쪽만 붉게 칠해지는지
- [ ] 설명 문구가 카드에 따라 바뀌는지 / 언어를 바꾸면 이름·설명도 바뀌는지
- [ ] `이 캐릭터로 시작` → 진행도 초기화 + 월드맵으로 넘어가는지
- [ ] `뒤로` → 타이틀로 돌아오고 **진행도는 그대로**인지 (아직 안 지워졌어야 한다)
- [ ] 게임을 껐다 켜도 고른 캐릭터가 유지되는지

### 8-2. 전투 그림

- [ ] 기사로 시작 → 전투에서 왼쪽 플레이어가 `player_knight` 인지
- [ ] 낭인으로 다시 시작 → `player_sekiro` 로 바뀌는지

### 8-3. NPC 반응 (여기가 이번 핵심)

- [ ] 준비 화면 왼쪽 성녀가 **고른 캐릭터에 따라 다른지** (기사=`darksouls_saint` / 낭인=`sekiro_shaman`)
- [ ] **+ATK 또는 +DEF** 를 누르면 **성녀**가 튀어오르며 번쩍이는지
- [ ] **+PARRY** 를 누르면 **대장장이**가 튀어오르며 번쩍이는지 (색이 더 주황빛)
- [ ] 연타해도 자리가 밀리거나 크기가 이상하게 남지 않는지
- [ ] 반응 도중 FIGHT 를 눌러도 다음에 준비 화면이 멀쩡한지

> 튜닝: 반응의 세기는 씬의 `SaintNpc/Body` · `BlacksmithNpc/Body` 에 붙은
> **`NpcReaction`** 인스펙터에서(`punchScale` / `hopHeight` / `duration` / `flashColor`).
> 나중에 스프라이트 시트가 생기면 같은 컴포넌트의 `animator` 슬롯만 채우면 그쪽이 우선한다.

### 8-4. 패링 — 띠(겹침 = 판정) + 즉시 결판

회색이 **얇은 원**이 아니라 **두께 있는 띠**로 바뀌었고, 띠의 범위가 곧 실제 판정 범위다
— 바깥 = 가장 이른 성공, 안쪽 = 가장 늦은 성공(유예 포함).
그리고 **누른 순간 성공/실패가 결판난다** (예전에는 타격 시점까지 기다렸다).

- [ ] 판정 안에서 누르면 **그 자리에서** 「PARRY」가 뜨고 **흰 원이 즉시 사라지는지**
      (원이 끝까지 줄어드는 것을 보고 있지 않아도 되는지)
- [ ] 흰 원이 **띠에 겹쳐 있는 동안** 누르면 되는지 — 특히 **띠 안쪽 끝**에서도
- [ ] 띠보다 **바깥**에서 미리 누르면 실패하고, **잠깐 잠겨서 연타가 안 되는지**
      (헛침 잠금 0.35초 — `PlayerStatsConfig ▸ parryWhiffLockSeconds`)
- [ ] 흰 원이 띠를 **완전히 지나간 뒤** 누르면 실패하는지
- [ ] Flurry 3연타에서 **세 번 따로** 눌러야 하고, 한 번 누를 때마다 원이 하나씩 사라지는지
- [ ] 회색이 너무 진하거나 흐리지 않은지 (`CombatScreen ▸ parryBandColor`, 기본 알파 0.15)

**판정량 하향 (2단계)**

1. 레벨당 증가폭 `0.03 → 0.015`초 (캡 5레벨: 0.40 → 0.325초)
2. **+PARRY 1레벨에 2포인트** (+ATK/+DEF는 1포인트 그대로)
   — 폭을 더 깎으면 성장이 눈에 안 보이므로, 대신 값을 비싸게 매겨 **오르는 속도**를 늦춘다.
   같은 판을 굴렸을 때 예전 5레벨 자리가 이제 2~3레벨쯤이 된다.

- [ ] +PARRY 버튼에 **`2P`**가 표시되는지 / 포인트가 1개일 때 **눌리지 않는지**
- [ ] 포인트 1개일 때 +PARRY가 `MAX`가 아니라 **그냥 비활성**으로 보이는지 (상한과 구분)
- [ ] 캡(5레벨)에 도달하면 그때는 `MAX`로 바뀌는지
- [ ] 한 판 굴려 보고 **판정이 아직도 후한지** — 후하면 `parryPointCost`를 3으로,
      그래도 넓으면 `baseParryWindowSeconds`(0.25)를 손대는 순서로
- [ ] +PARRY를 찍었을 때 **띠가 굵어지는 것이 여전히 보이는지**

> 여전히 안 맞으면 **`approachSpeed`가 아니라 판정 자체**를 의심할 것 —
> 띠는 판정에서 계산되므로 둘이 어긋날 수 없다.
> 손에 안 맞으면 `PlayerStatsConfig ▸ baseParryWindowSeconds`(0.25) /
> `parryLateGraceSeconds`(0.12) / `parryWindowPerLevelSeconds`(0.015) 를 조절한다.
> 실제 아트로 띠를 갈아 끼우면 `CombatScreen ▸ generateBandSprite` 를 꺼야 덮어쓰지 않는다.

### 8-5. 캐릭터 특화

공용 밸런스에 **더해지는** 아주 작은 차이(대략 반 레벨)다.

| | 기사 | 낭인 |
|---|---|---|
| 최대 체력 | +12 | — |
| 피해 감소 | +1.0 (DEF 반 레벨) | — |
| 공격력 | — | +1.5 (ATK 반 레벨) |
| 패링 폭 | — | +0.015초 (PARRY 반 레벨) |

- [ ] 기사로 시작 → 퍼즐 HUD의 **최대 체력이 112** 인지
- [ ] 낭인으로 시작 → 첫 전투의 **패링 띠가 기사보다 아주 살짝 두꺼운지**
- [ ] 콘솔에 `[GameManager] 캐릭터 '...' 특화 적용.` 이 찍히는지
- [ ] 체감상 한쪽이 명백한 정답으로 느껴지지는 않는지 (그렇다면 수치를 더 줄일 것)

> 수치는 `Data/Resources/Characters/Character_*.asset` 인스펙터에서 바로 고친다.
> `Create Default Characters` 를 다시 돌려도 **손으로 고친 값은 덮어쓰지 않는다.**

### 8-6. 스탯 분배를 준비 화면으로 이동

> **`Main.unity` → `Build Main Scene UI` 재실행이 반드시 필요하다.**
> 안 돌리면 퍼즐 화면에 예전 버튼 3개가 **남아 있으면서 아무 반응도 안 한다**
> (PuzzleHud에서 필드가 빠져 배선이 끊긴 채로 남는다).

- [ ] 퍼즐 화면에 **+ATK/+DEF/+PARRY가 없는지** (HP·영혼석·턴·현재 수치 표시는 그대로)
- [ ] 보스 타일 도달 → 준비 화면에서 **FIGHT 아래에 버튼 3개**가 나오는지
- [ ] 거기서 눌러 스탯이 올라가고 라벨·잔여 포인트가 갱신되는지
- [ ] 뒤의 퍼즐판이 **살짝 어두워져** 준비 화면인 게 구별되는지 (판은 비쳐 보여야 한다)
- [ ] 어두운 동안 **퍼즐판을 건드려도 스왑이 안 되는지** (딤이 입력을 막는다)
- [ ] FIGHT를 누르면 어둠이 사라지고 전투로 넘어가는지
- [ ] 가로 화면에서도 버튼 3개와 NPC가 띠 안에 들어오는지

**상점처럼 — 화면 안에서 현황이 다 보이는지**

- [ ] 띠 안에 **체력 / Lv·영혼석·포인트 / 현재 공격·방어·패링**이 나오는지
- [ ] **남은 포인트가 금색으로 크게** 보이는지 (다 쓰면 "준비되면 시작하세요"로 바뀐다)
- [ ] 버튼을 눌러 스탯을 찍으면 **그 줄들이 즉시 갱신되는지** (공격 수치, 남은 포인트)
- [ ] 띠가 반투명이라 뒤 퍼즐판이 **어렴풋이 비치는지**

> 어둠의 세기: `IntermissionScreen ▸ dimColor` (기본 검정 알파 0.45).
> 띠 자체의 투명도는 씬의 `Band` 이미지 알파(0.88).
> UI는 나중에 확장할 자리다 — 지금은 필요한 숫자만 올려 둔 상태.

### 8-7. 월드맵 — 잠긴 노드를 누른 뒤 원래 스테이지로 복귀

**증상**: 1-1에 서서 1-2(잠김)를 누르면 LOCKED가 뜨는데, 1-1을 다시 눌러도
아무 반응이 없어 START를 되살릴 수 없었다. 서 있는 노드를 누르면 무시하고 있었다.

- [ ] 1-1에서 1-2(잠김) 클릭 → 튕기고 `LOCKED` + START 비활성
- [ ] **1-1을 다시 클릭** → 정보 패널이 1-1로 돌아오고 **START가 다시 눌리는지**
- [ ] 그 상태로 START → 1-1이 정상적으로 시작되는지
- [ ] 열린 노드 사이를 오갈 때는 예전처럼 걸어가고 패널이 갱신되는지

### 8-8. 타일 배경판 (아트 대기 중 — 지금은 배선만)

아이콘만 있어서 타일 경계가 안 읽히는 문제. **그림은 사용자가 나중에 넣는다.**
배선은 끝나 있고, 아래처럼 즉시 확인할 수 있다.

**가장 빠른 확인** — 그림 없이 색만으로:

- [ ] `Data/Tile_*.asset` 아무거나 열고 **`Background Color`의 알파를 올린다**
      (예: 어두운 남색 알파 0.5) → 보드에서 그 타일 뒤에 받침이 깔리는지
- [ ] 타일이 **떨어지고 스왑될 때 받침이 같이 따라가는지** (배경 셀과 달리 타일에 붙어 있다)
- [ ] 6종 타일에 서로 다른 색을 넣었을 때 **구별이 확실히 나아지는지**

**그림을 넣을 때**:

- [ ] 타일마다 다르게 → `Tile_*.asset ▸ Background Sprite`
- [ ] 전부 같은 받침 하나로 → `BoardView ▸ Tile Background Sprite` (타일 전용이 우선한다)
- [ ] 받침이 아이콘보다 살짝 커 보이는지 (`BoardView ▸ Tile Background Scale`, 기본 1.05)
- [ ] 벽에는 안 깔리는 게 맞는지 (벽은 셀을 꽉 채우는 지형 — 필요하면 `Background On Walls` 켜기)

> 우선순위: 타일 SO의 전용 그림 → BoardView 공용 그림 → (그림이 없으면) 색만 있는 사각형.
> 알파가 0이면 아무것도 안 그리므로 **아무것도 안 하면 지금과 똑같이 보인다.**

```
[콘솔] (에러 메시지 있으면 첫 줄만)
```
