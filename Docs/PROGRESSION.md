# PROGRESSION.md — 성장 캐리 + 사슬 (런 스파인)

> ChainRiposte에 "목적성"을 부여하는 상위 설계. 지금까지 게임은 **매 스테이지가 닫힌 캡슐**
> (소울 벌기 → 그 판 보스에 다 쓰기 → 리셋)이라 다음 판을 갈 이유도, 엔딩이 정산할 여정도 없었다.
> 이 문서가 그 여정을 정의한다. 세션이 바뀌어도 이 파일이 기준이다.

## 0. 두 줄 원칙 (넘지 말 것)

1. **난이도는 실행(패링)에서 온다. 소울은 모서리만 깎는다** — 스탯으로 쉬움을 "사는" 게 아니다.
   최종 보스에 도달했을 때 빌드는 *강하지만 만렙은 아닌* 상태여야 한다.
2. **숫자는 전부 데이터(SO). 코드에 밸런스 상수를 박지 않는다** — 경제·난이도·사슬·엔딩 조건까지.
   튜닝은 인스펙터에서만. (프로젝트 기존 원칙과 동일: `~SO.ToConfig()`로 순수 C#에 주입)

## 1. 스파인: "사슬을 오르는 자"

너는 사슬을 오르는 자. 각 보스 = 사슬의 한 고리. 벤 보스의 **넋(소울)을 흡수해 영구히 강해지고**,
그 힘으로 다음 고리를 벤다. 최종 고리에서 이 모든 걸 정산한다.

이 한 문장이 **성장(A)**과 **서사(C)**를 묶는다. "소울이 왜 다음 판으로 남지?" → "벤 자의 넋을 삼켰으니까."
게임 이름 *ChainRiposte*(되받아치는 사슬)가 곧 진행 구조다.

## 2. 시스템 (풀 세트)

### 2.1 소울 은행 — 캐리 (즉각적 throughline)
- 퍼즐에서 번 소울이 그 판에서 안 쓰이면 사라지지 않고 **은행에 적립**. 스탯 레벨도 판을 넘어 유지.
- 퍼즐을 잘 풀면 **바로 다음 판이 편해진다** → "다음 판 갈 이유"가 이 하나로 즉시 생김.
- 저장 단위 = **캐릭터별 런 상태**(§4).

### 2.2 넋 — 보스별 영구 패시브 (성장 + 서사 + 리플레이)
- 보스 인살 시 큰 소울 + 그 보스의 **"넋" = 영구 패시브 1개** 획득. (로그라이크 유물의 가벼운 버전)
- **규칙: 넋은 개성·전술이지 평타 파워업이 아니다.** "공격력 +10" 금지 — 스노볼을 키운다.
  허용 예: "패링 성공 시 체간 추가 타격", "헛침 잠금 −20%", "연속 3패링 시 다음 피격 무효".
- 엔딩에서 흡수한 넋들이 정산 연출로 스쳐 지나간다.
- **데이터**: `SoulRelicSO` 1개 = 넋 1개. 보스(`BossDataSO`)가 자기 넋을 참조. 효과는 전투 시스템이 읽는
  플래그/수치 집합(순수 C# `SoulRelicConfig`)으로 주입.

### 2.3 사슬 배수 — 이름값 + 긴장
- 죽지 않고 연속 클리어하면 소울/보상 **배수↑**. 죽으면 배수만 끊김(빌드는 유지).
- "노 데스"라는 세키로다운 목표. **데이터**: 배수 곡선은 `RunEconomyConfigSO`.

### 2.4 소울 경제 — "항상 살짝 모자라게"
목표: 최종 보스 도달 시 *강하지만 만렙 아님*. 스킬이 끝까지 관문.
- **매치당 소울 인컴 ↓** (지금 후한 편) — `RunEconomyConfigSO.soulIncomeMultiplier`.
- **레벨 요구량 상승 곡선** — 이미 `PlayerStatsConfig.BaseSoulsToLevel + Growth*(Level-1)`. 후반 레벨이 sink.
- **+PARRY는 특히 비싸게** — 패링 창은 "실수 자체를 지우는" 스탯이라 싸면 무조건 사서 쉬워진다.
  이미 `ParryPointCost=2`. 필요 시 상향. 창 증가폭(`ParryWindowPerLevelSeconds`)은 캡을 먼저 본다.
- 결과: 판마다 "HP를 더 살까, 패링 창을 넓힐까"가 진짜 선택이 되고, 아무것도 그냥 사지 못함.

### 2.5 실패 처벌 · 보스 난이도 스케일링 (체감 난이도의 본체)
현재 너무 쉬움. 시스템으로 올릴 수 있는 레버(= 채보 아님):
- **피격/헛침 처벌 ↑**: 패링 실패 시 HP 더 깎이고, 헛치면 보스 체간이 회복. (지금 실수가 안 아픔)
- **보스 체간·공격력 사슬 스케일링**: 고리 깊이(스테이지 순서)마다 +체간/+피해. HP는 "길이"라 과하게 안 올림.
- **노트 속도(BPM) 배수**: 고리 깊이에 따라 전역 템포 배수(리듬 게임의 speed mod). 채보를 안 건드리고도 조임.
- **임시 패턴을 험하게**: Boss_02/03이 임시 정박 4타라 지금 거저. 이것만 험하게 해도 체감 급상승.
- **데이터**: 위 스케일링은 `DifficultyCurveSO`가 *고리 깊이 → 배수 4종(HP/체간/피해/템포)*으로 보유.
  실패 처벌 절대값은 `PlayerStatsConfig`/`BossConfig`에.

### 2.6 엔딩 + NG+
- 최종 스테이지(현재 2-3, 2페이즈 보스)를 **"사슬 끝"으로 승격**.
- 마지막 인살 → **기존 인살 컷씬 기술 재활용** → "사슬이 끊겼다" + 흡수한 넋들이 스쳐감 → 크레딧 →
  타이틀 복귀, **캐릭터별 결말 문구** + NG+(2회차, `DifficultyCurveSO`에 회차 배수) 해금.
- **데이터**: "무엇이 최종 고리인가"는 코드 하드코딩 금지 — 정렬된 스테이지 목록의 마지막, 또는
  `StageDataSO.isFinalLink` 플래그. 스테이지를 추가/재배치해도 엔딩 조건이 안 깨지게.

## 3. 데이터 주도 배치 (어느 SO가 무엇을 갖나)

| 관심사 | SO | 대표 값 |
|---|---|---|
| 플레이어 성장 밸런스 (기존) | `PlayerStatsConfigSO` | 레벨 요구량·성장, 스탯 비용, 패링창, 실패 처벌 절대값 |
| **런 경제 (신규)** | `RunEconomyConfigSO` | 소울 인컴 배수, 사슬 배수 곡선, 시작 소울, 죽음 시 손실 |
| **난이도 곡선 (신규)** | `DifficultyCurveSO` | 고리 깊이 → HP/체간/피해/템포 배수, NG+ 회차 배수 |
| **넋 (신규)** | `SoulRelicSO` (여러 개) | 패시브 1개의 효과 플래그/수치 |
| 스테이지 | `StageDataSO` | `isFinalLink`(엔딩 트리거), 보스 참조 |
| 보스 | `BossDataSO` | 드랍하는 넋(`SoulRelicSO`) 참조 |

> 원칙: **새 밸런스 축이 생기면 코드 상수가 아니라 SO 필드로.** Core는 이 SO들을 모른다 —
> Game 레이어가 `ToConfig()`로 순수 C# 구조체(`RunEconomyConfig`/`DifficultyConfig`/`SoulRelicConfig`)를 만들어 주입.

## 4. 캐리 아키텍처

현재: `GameManager.Awake`가 스테이지마다 `new GameSession(config)` → 소울·레벨 리셋.
바꿀 것 = **런 상태를 저장/복원해 씨앗으로 넣기.**

```
RunState (Core, 순수 C#)          — 한 런의 누적 상태
  ├ statLevels[3]                 — ATK/DEF/Parry 레벨
  ├ soulBank, level, pendingPoints
  ├ acquiredRelicIds[]            — 획득한 넋
  ├ chainMultiplierStep           — 현재 사슬 배수 단계 (죽으면 0)
  ├ newGamePlusCount              — NG+ 회차
  └ Serialize()/Deserialize()     — 문자열 왕복 (ProgressService와 같은 방식)

RunStateService (Game, PlayerPrefs 어댑터)  — 캐릭터별 키. ProgressService 옆에.
  ├ Current, Save(RunState), Reset(), StartNewRun()

PlayerStats (Core) — 저장 상태로 복원하는 생성 경로 추가
  └ new PlayerStats(config, RunState seed)  — 레벨/소울/포인트/스탯레벨을 주입

GameManager
  ├ Awake:  RunStateService.Current 로드 → GameSession에 seed 주입
  ├        DifficultyCurveSO로 고리 깊이만큼 보스 config 스케일
  └ Victory: RunState 갱신(누적 소울·레벨·넋·사슬 배수++) → 저장.  Defeat: 사슬 배수만 0.
```

- **HP는 캐리 안 함**: 준비 화면 = 휴식. 매 전투 만피 시작(현재 동작 유지).
- **캐릭터별 저장**: 런 상태는 캐릭터에 묶인다(기사/낭인 각자 런). `ProgressService`(클리어 집합)도 이미 진행도.

## 5. 죽음 · 재도전 모델 (확정)

- **죽으면**: 빌드(스탯·소울 은행·넋) **전부 유지**, **사슬 배수만 0으로**, 스테이지 재도전. (세키로식, 좌절 최소)
- **재도전 시 퍼즐 다시 안 푼다**: 보스에서 죽으면 **보스만 재도전**, 이미 분배한 스탯 유지.
  → **소울 무한 파밍 차단**(퍼즐은 그 판에 한 번만). 이게 경제의 성패를 가른다.
  - 구현 노트: 재도전 진입 시 `GamePhase.Combat`부터 시작하는 경로 필요(현재 `Defeat`는 종료 상태).

## 6. 밸런스 노브 (튜닝 표 — 전부 인스펙터)

| 쉽다고 느끼면 조일 순서 | 노브 | 위치 |
|---|---|---|
| 1. 성장이 너무 빠름 | `soulIncomeMultiplier` ↓ | `RunEconomyConfigSO` |
| 2. 실수가 안 아픔 | 피격 피해 ↑, 헛침 시 보스 체간 회복 | `BossConfig`/`PlayerStatsConfig` |
| 3. 보스가 물렁 | 고리 깊이별 체간/피해/템포 배수 ↑ | `DifficultyCurveSO` |
| 4. 패링을 돈으로 삼 | `ParryPointCost` ↑, `ParryWindowPerLevelSeconds`(캡) ↓ | `PlayerStatsConfigSO` |
| 5. 후반이 그냥 압도 | 레벨 요구량 성장 ↑ | `PlayerStatsConfigSO` |

## 7. 빌드 순서 + 몫 나누기

앞이 뒤의 전제:
1. **`RunState` 캐리 시스템** — 스탯/소울이 판을 넘어 유지 + 세이브. (난이도 중립, 모든 것의 기반) ← 착수
2. **소울 경제 손질** — `RunEconomyConfigSO` + 인컴 배수 + 사슬 배수.
3. **난이도** — `DifficultyCurveSO`(고리 깊이별 배수) + 실패 처벌 상향 + 임시 패턴 험하게.
4. **넋 시스템** — `SoulRelicSO` + 보스 드랍 + 전투 반영.
5. **엔딩 + NG+** — 사슬 끝 승격, 인살 컷씬 재활용, 캐릭터별 문구, 회차 배수.

**내 몫(시스템·데이터 배관·튜닝 노브)** ↔ **당신 몫(채보 밀도/속도 = 어려움의 본체)**. §2.5의 시스템 레버로
채보 전이라도 "거저"는 면하게 만든다.

## 8. 열린 결정 (지금 안 막아도 됨)

- 넋 효과 최종 목록(1차엔 2~3개만).
- NG+가 넋을 리셋하나 유지하나.
- 사슬 배수 곡선 구체 수치.
- 최종 고리를 현재 2-3로 둘지, 월드3 전용 최종보스를 나중에 추가할지.
